# DSS: Система підтримки прийняття рішень — Підбір резервного живлення

Десктопний додаток на базі **PyQt6** для підбору оптимального обладнання резервного живлення для дому.
Система ставить користувачу ряд запитань про його потреби та, на основі правил логічного виведення, рекомендує найбільш підходящі варіанти обладнання з поясненнями.

## Архітектура проекту

Проект побудований за **тришаровою архітектурою** з чітким розділенням відповідальності:

```
┌─────────────────────────────────────────┐
│              main.py                    │  Точка входу
│         (ініціалізація)                 │
└────────────┬────────────────────────────┘
             │
┌────────────▼────────────────────────────┐
│            ui/ (Шар UI)                 │  Відображення та взаємодія
│  gui.py, gui_welcome.py,               │  з користувачем
│  gui_questionnaire.py, gui_results.py, │
│  gui_admin.py, gui_theme.py,           │
│  gui_styles.py                         │
└────────────┬────────────────────────────┘
             │
┌────────────▼────────────────────────────┐
│          core/ (Шар логіки)             │  Бізнес-логіка та дані
│  engine.py  — рушій виведення           │
│  database.py — доступ до даних (DAO)    │
│  models.py  — dataclass-моделі         │
│  config.py  — константи конфігурації    │
└────────────┬────────────────────────────┘
             │
┌────────────▼────────────────────────────┐
│         SQLite (dss_energy.db)          │  Зберігання даних
└─────────────────────────────────────────┘
```

**Принцип роботи:**
1. `main.py` створює з'єднання з БД, ініціалізує схему та початкові дані
2. Створює `InferenceEngine` (рушій виведення) та `MainWindow` (головне вікно)
3. Користувач відповідає на запитання → рушій обчислює бали → UI показує рекомендації

## Структура бази даних

База даних SQLite складається з 5 таблиць:

```
┌──────────────┐     ┌────────────────────┐
│  questions   │     │  question_answers  │
├──────────────┤     ├────────────────────┤
│ id (PK)      │◄────│ question_id (FK)   │
│ text         │     │ id (PK)            │
│ category     │     │ value              │
└──────┬───────┘     │ label              │
       │             └────────────────────┘
       │
       │             ┌──────────────┐
       │             │   options    │
       │             ├──────────────┤
       │             │ id (PK)      │
       │             │ text         │
       │             │ description  │
       │             └──────┬───────┘
       │                    │
       ▼                    ▼
┌─────────────────────────────────┐     ┌──────────────┐
│            rules               │     │   admins     │
├─────────────────────────────────┤     ├──────────────┤
│ id (PK)                        │     │ id (PK)      │
│ question_id (FK → questions)   │     │ username     │
│ answer_value                   │     │ password_hash│
│ option_id (FK → options)       │     └──────────────┘
│ score_adjustment               │
└─────────────────────────────────┘
```

### Опис таблиць

| Таблиця | Призначення |
|---------|-------------|
| `questions` | Запитання для користувача. Кожне має текст і категорію (бюджет, потужність, комфорт, ...) |
| `question_answers` | Варіанти відповідей на запитання. Містить `value` (код: `"a"`, `"b"`, `"dk"`) та `label` (текст для UI) |
| `options` | Обладнання (рішення). Містить назву та детальний опис |
| `rules` | Правила нарахування балів. Зв'язує тріаду `(запитання, відповідь, обладнання)` із значенням `score_adjustment` |
| `admins` | Облікові записи адміністраторів. Паролі зберігаються як SHA-256 хеші |

### Шкала балів (score_adjustment)

| Бал | Значення |
|-----|----------|
| `+15` | Ідеальна відповідність |
| `+5` | Добра відповідність |
| `0` | Нейтрально (правило не створюється) |
| `-5` | Погана відповідність |
| `-1000` | Повністю недоречний варіант (фактично виключає) |

## Як працює InferenceEngine

`InferenceEngine` — це рушій логічного виведення, який обчислює рекомендації на основі відповідей користувача та правил у базі даних.

### Алгоритм оцінювання (`evaluate`)

```
Вхід: answers = {question_id: answer_value}  (наприклад: {1: "a", 2: "c", 3: "dk"})
Вихід: List[Recommendation] — відсортований список рекомендацій
```

**Крок 1 — Ініціалізація:**
- Для кожного обладнання встановити початковий бал `score = 0.0`

**Крок 2 — Нарахування балів:**
- Для кожної відповіді (крім `"dk"` — «Не знаю»):
  - Знайти всі правила для пари `(question_id, answer_value)` у таблиці `rules`
  - Для кожного правила додати `score_adjustment` до балу відповідного обладнання
  - Зберегти пояснення (категорія, текст відповіді, бал)

**Крок 3 — Обчислення максимально можливих балів:**
- Метод `_calculate_absolute_max_scores()` обчислює теоретичний максимум для кожного обладнання
- Для кожної пари `(option_id, question_id)` знаходиться максимальне додатне `score_adjustment`
- Ці максимуми підсумовуються — це найкращий бал, який може отримати обладнання, якщо користувач дасть «ідеальні» відповіді

**Крок 4 — Конвертація у відсотки:**
```
якщо score ≤ 0:
    percentage = 0%
інакше:
    percentage = min(100%, (score / max_possible_score) × 100%)
```

**Крок 5 — Формування пояснень:**
- Кожне пояснення форматується як:
  - `✅ Категорія: Відповідь (+15 балів)` — для позитивних балів
  - `❌ Категорія: Відповідь (-5 балів)` — для негативних балів
- Пояснення сортуються від найбільшого до найменшого балу

**Крок 6 — Сортування та повернення:**
- Рекомендації сортуються за `percentage` у спадному порядку
- Метод `get_top_recommendations()` фільтрує лише варіанти з додатним балом та обмежує кількість

### Приклад роботи

```
Відповідь: "Освітлення та зарядка гаджетів" (Q1 = "a")

Правила для Q1="a":
  → Портативна зарядна станція 1кВт:  +15  (ідеально)
  → Портативна сонячна станція 500Вт: +15  (ідеально)
  → ДБЖ (UPS) 1.5кВт:                 +5  (добре)
  → Інверторний генератор 2кВт:        +5  (добре)
  → Дизельний генератор 5кВт:          -5  (погано)
  → Гібридний інвертор 5кВт:           -5  (погано)
  → Газовий генератор 6кВт:            -5  (погано)
```

## Генератор правил

Файл `saves/generate_rules.py` — це допоміжний скрипт для автоматичної генерації правил на основі **атрибутів обладнання**. Він НЕ є частиною рантайму додатку, а використовується як одноразова утиліта розробника.

### Принцип роботи

1. **Завантажує** існуючий `save.json` з запитаннями та обладнанням
2. **Визначає атрибути** для кожного з 37 типів обладнання:

| Атрибут | Можливі значення | Опис |
|---------|-----------------|------|
| `type` | `battery`, `generator`, `solar`, `battery_solar` | Тип обладнання |
| `fuel` | `True` / `False` | Чи потребує палива |
| `power` | Вт (напр. 1000, 5000) | Потужність |
| `capacity` | Вт·год (напр. 300, 5120) | Ємність акумулятора |
| `noise` | `silent`, `quiet`, `moderate`, `loud` | Рівень шуму |
| `phase` | `1`, `3` | Однофазний чи трифазний |
| `automation` | `none`, `avr`, `full` | Рівень автоматики |
| `portability` | `hand`, `wheels`, `stationary` | Портативність |
| `pure_sine` | `True` / `False` | Чиста синусоїда |
| `zero_transfer` | `True` / `False` | Нульовий час перемикання |
| `price_tier` | `low`, `mid`, `high`, `premium` | Цінова категорія |

3. **Генерує правила** для кожної пари `(запитання, обладнання)` на основі логічних умов. Наприклад:

```python
# Запитання 1: "Яка основна мета?"
# Відповідь "a" (Освітлення та зарядка):
if attrs["fuel"]:             # генератори зайві для освітлення
    score = -1000
elif attrs["portability"] == "hand":  # портативні — ідеально
    score = +15
else:
    score = +5

# Запитання 4: "Рівень шуму?"
# Відповідь "a" (Тиша дуже важлива):
if noise == "silent": score = +15    # акумулятори
elif noise == "quiet": score = -5    # інверторні генератори
else: score = -1000                  # гучні генератори — недоречно
```

4. **Зберігає** оновлений `save.json` з новими правилами

### Логіка для 12 запитань

| # | Запитання | Ключові атрибути для оцінки |
|---|-----------|---------------------------|
| 1 | Мета використання | `type`, `fuel`, `portability` |
| 2 | Бюджет | `price_tier` |
| 3 | Потужність | `power` (пороги: 500, 2000, 3500, 5000 Вт) |
| 4 | Тривалість автономії | `capacity`, `fuel` (пороги: 300, 800, 1500, 3000 Вт·год) |
| 5 | Зберігання палива | `fuel` |
| 6 | Автоматичне перемикання | `automation` |
| 7 | Рівень шуму | `noise` |
| 8 | Фазність | `phase` |
| 9 | Сонячне світло | `type` (solar/battery_solar) |
| 10 | Портативність | `portability` |
| 11 | Якість електроенергії | `pure_sine`, `zero_transfer` |
| 12 | Частота/тривалість відключень | `portability`, `automation` |
